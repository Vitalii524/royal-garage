# Безпечний випуск

Це план, не підтвердження виконаного резервного копіювання.

- До SQL-міграцій потрібна consistent PostgreSQL custom-format копія через pg_dump або підтверджений експорт провайдера; не копіювати .env.
- Зберігати backup приватно з обмеженими правами, не в Git, не в публічному звіті. Зафіксувати контрольну суму, час і версію PostgreSQL 18.
- Пробне pg_restore виконати лише у нову ізольовану БД; звірити кількість користувачів, профілів, товарів, market_listings, chat_messages, CRM-авто/клієнтів/нарядів та історії.
- Staging не повинен надсилати email/SMS/Push реальним користувачам та не повинен мати LiqPay-ключів.
- Застосувати міграції у транзакції; резервну копію і rollback версію зафіксувати до запуску.
- Повернення коду не повинно видаляти нові записи. Не виконувати DROP таблиць/grants як rollback. У разі проблем вимкнути нові екрани та акції; дані зберегти.
- Відновлення всього backup на prod потребує окремого погодження, оскільки перезапише нові події після backup.
- Після випуску порівняти кількості/хеші існуючих даних. Фактичний запуск акції зафіксувати один раз після погодження юридичних умов.
